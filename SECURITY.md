# Security policy

## Scope

This project publishes documentation now, and will publish specifications, test files and reference code later. Security reports are welcome for:

- **design flaws** in proposed formats or protocols, such as ways to forge credentials, track players or exploit avatar loading
- **vulnerabilities** in any reference code or tools in this repository
- **unsafe test files**, meaning test assets that could harm a tool that loads them in ways the docs don't describe
- **accidentally published secrets or personal data**

## How to report

**Please don't open a public issue.** Use GitHub's private reporting instead:

1. Go to this repository's **Security** tab.
2. Click **Report a vulnerability**.
3. Describe the issue, how to reproduce it, and the impact.

Only maintainers can see these reports. We aim to acknowledge reports within **7 days**. Please give us a reasonable amount of time to fix an issue before disclosing it publicly.

## Supported versions

Nothing in this repository has been released yet. We'll update this section when specifications or code get versioned releases.

## No bug bounty

This is a volunteer community project and has no bug bounty program. We're happy to credit reporters in release notes, if you'd like that.
